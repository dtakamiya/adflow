# 完了前検証スキル

## ビルドシステム
!`ls build.gradle build.gradle.kts pom.xml package.json pyproject.toml setup.py Cargo.toml go.mod Makefile *.csproj *.sln 2>/dev/null`

## 鉄則（絶対ルール）

1. **証拠なき完了宣言は禁止** — 検証コマンドを実行せずに「完了」「成功」「問題なし」と主張することは、効率化ではなく虚偽報告である。
2. **前回の実行結果を流用しない** — 「さっき通ったから大丈夫」は無効。現在のセッションで新たに実行した結果のみが証拠として有効。
3. **部分的な確認で全体を保証しない** — Lintが通っても、テストが通っているとは限らない。各主張にはそれぞれ対応する検証が必要。
4. **推測表現を使わない** — 「おそらく」「〜のはず」「問題ないと思う」は検証不足のシグナル。

## Red Flags — よくある合理化

| 思考 | 現実 |
|------|------|
| 「さっきテスト通ったから大丈夫」 | その後にコードを変更した。再実行が必要 |
| 「この変更は小さいから影響ない」 | 小さな変更が大きなバグを生む。検証は必須 |
| 「ビルドが通ったからOK」 | ビルド成功 ≠ テスト成功 ≠ 仕様準拠 |
| 「Done! 完璧です！」 | 感情表現は証拠ではない |
| 「エージェントの報告を信頼する」 | エージェントの出力も検証が必要 |

## 検証ゲート（The Gate Function）

完了を宣言する前に、以下のゲートを通過すること:

```
1. 主張を特定する     → 「何が完了したのか」を明確にする
2. 検証コマンドを特定する → 「何を実行すれば証明できるか」を決める
3. コマンドを実行する   → 実際に実行する（省略禁止）
4. 出力を完全に読む    → 終了コードとフル出力を確認する
5. 出力が主張を裏付ける → 出力が主張と一致していることを確認する
6. 主張を証拠付きで報告 → 実行結果を添えて報告する
```

**ゲートの任意のステップをスキップした場合、検証は無効。**

## 主張と必要な証拠の対応表

| 主張 | 不十分な証拠 | 必要な証拠 |
|------|------------|-----------|
| 「テストが全て通っている」 | 前回の実行結果 / コード変更だけ | テスト実行出力（失敗0件の表示） |
| 「Lintエラーなし」 | 部分的なLint実行 | Lint全体実行出力（エラー0件の表示） |
| 「ビルド成功」 | テスト結果だけ | ビルドコマンドの終了コード 0 |
| 「バグ修正完了」 | コード変更だけ | 再現テストの実行結果（成功） |
| 「仕様通りの実装」 | コードの確認だけ | 仕様書の各要件に対応するテスト結果 |
| 「セキュリティ問題なし」 | コードレビューだけ | セキュリティスキャン実行結果 |

## 検証の実行

### 引数ありの場合

`$ARGUMENTS` が提供された場合、その主張に対して上記のゲートを適用する。

### 引数なしの場合

現在の作業状態を確認し、以下の標準検証セットを実行する:

1. **ビルド検証**: プロジェクトがビルドできること
2. **テスト検証**: 全テストが通ること
3. **Lint検証**: コーディング規約に準拠していること
4. **差分検証**: `git diff` で意図しない変更がないこと

## 検証結果の報告フォーマット

```markdown
# 完了前検証結果

| 検証項目 | コマンド | 結果 | 証拠 |
|---------|---------|------|------|
| ビルド | `{command}` | PASS/FAIL | 終了コード: {N} |
| テスト | `{command}` | PASS/FAIL | {passed}/{total} テスト成功 |
| Lint | `{command}` | PASS/FAIL | エラー: {N}件 |
| 差分 | `git diff --stat` | PASS/WARN | {N}ファイル変更 |

**総合判定**: VERIFIED / NOT VERIFIED
```

## 他スキルとの連携

このスキルは以下のスキルの完了時に自動的に参照される:

- `/stack-loop` — 各PR完了時の最終検証（Step 4 の検証ループと併用）
- `/systematic-debugging` — Phase 4 修正完了時のリグレッション確認
- 任意のタスク完了時 — ユーザーが明示的に検証を要求した場合
