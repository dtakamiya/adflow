# ADRフィットネス関数パターン

ADRの決定事項が実装で正しく守られているかを自動検証する仕組み。
CI/CDパイプラインに組み込み、アーキテクチャドリフト（設計と実装の乖離）を早期検出する。

## フィットネス関数とは

ADRで記録した設計判断を **テスト可能なルール** として定義し、コミットごとに自動実行するチェック。
判定結果が明確（Pass/Fail）で、継続的に実行される点が通常のコードレビューとの違い。

## パターン一覧

### 1. 静的解析フィットネス関数

ソースコードの構造やパターンを解析し、ADRの制約に違反していないかをチェックする。

```
# 例: ADR-0001「金額計算にはBigDecimalを使用する」のフィットネス関数
検証対象: 金額関連フィールド・変数の型宣言
違反パターン: double/float型で金額を扱うコード
検出方法: AST解析 or 正規表現パターンマッチ
実行タイミング: pre-commit / CI
```

**実装例（言語非依存の疑似コード）:**
```
function check_decimal_usage(source_files):
    violations = []
    for file in source_files:
        for line in file.lines:
            if matches(line, /amount|price|balance|fee|total/i):
                if matches(line, /double|float|Float|Double/):
                    violations.add(file, line_number, "金額計算にdouble/floatを使用")
    return violations
```

### 2. 依存関係フィットネス関数

レイヤー間の依存方向がADRの設計に準拠しているかを検証する。

```
# 例: ADR-0002「レイヤードアーキテクチャの依存方向」
ルール:
  - Controller → UseCase: 許可
  - UseCase → Service: 許可
  - Service → Repository: 許可
  - Repository → Controller: 禁止（逆方向依存）
  - Service → Controller: 禁止（逆方向依存）
検出方法: import文の解析
```

### 3. テストカバレッジフィットネス関数

ADRで定めたテスト要件が満たされているかを検証する。

```
# 例: ADR-0003「すべての状態変更操作にテストを必須とする」
ルール:
  - 状態変更メソッドに対応するテストが存在すること
  - トランザクションロールバックテストが存在すること
  - 監査ログ出力テストが存在すること
検出方法: テストファイルとソースファイルの対応関係チェック
```

### 4. セキュリティフィットネス関数

セキュリティ関連ADRの準拠を検証する。

```
# 例: ADR-0004「PII（個人情報）は暗号化して保存する」
ルール:
  - PIIフィールドに@Encrypted（または同等の暗号化処理）が適用されていること
  - ログ出力にPIIフィールドが直接含まれていないこと
検出方法: アノテーション / デコレータの有無チェック + ログ文の解析
```

### 5. 監査ログフィットネス関数

監査要件ADRの準拠を検証する。

```
# 例: ADR-0005「すべての状態変更に監査ログを記録する」
ルール:
  - CREATE/UPDATE/DELETE操作を行うメソッドに@Audited（または監査ログ呼び出し）があること
  - 監査ログが独立トランザクションで記録されること
検出方法: メソッドのアノテーション / 呼び出しパターン解析
```

## CI/CDパイプラインへの統合

### pre-commitフック
```
# .pre-commit-config.yaml の例
- 金額計算にdouble/floatが使われていないか
- PIIフィールドが平文でログに出力されていないか
- トランザクション宣言が必要なメソッドに適用されているか
```

### CIパイプライン
```
# ビルドパイプラインのステージとして実行
stages:
  - lint
  - test
  - fitness-functions  ← ADR準拠チェック
  - build
  - deploy
```

### PRレビュー時の自動サーフェシング

Decision Guardianパターン: PRの変更差分に関連するADRを自動検出し、PRコメントとして表示する。
- 変更されたファイル/ディレクトリ → 関連ADRのマッピング
- ADRの決定事項をレビュアーに提示

## ADR → フィットネス関数の対応表

| ADRの決定事項 | フィットネス関数の種類 | 実行レベル |
|-------------|------------------|----------|
| 型制約（BigDecimal必須等） | 静的解析 | pre-commit |
| レイヤー依存方向 | 依存関係解析 | CI |
| テスト必須要件 | カバレッジチェック | CI |
| PII暗号化 | セキュリティ解析 | CI |
| 監査ログ必須 | パターンマッチ | CI |
| トランザクション宣言 | アノテーション検出 | pre-commit |
| API仕様準拠 | コントラクトテスト | CI |
