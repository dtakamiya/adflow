# セキュリティチェックリスト

## CRITICAL — リリース前に必ず確認

### C1. 認証・認可
- [ ] すべてのエンドポイントに認証が必要
- [ ] 権限チェックがビジネスロジック層で実装されている
- [ ] IDOR（Insecure Direct Object Reference）対策済み
- [ ] セッション管理が適切

### C2. データ保護
- [ ] 機密データ（PII等）が暗号化されている
- [ ] ログに機密データが出力されていない
- [ ] エラーレスポンスに内部情報（スタックトレース等）が含まれていない
- [ ] シークレットがソースコードにハードコードされていない

### C3. 入力バリデーション
- [ ] すべてのユーザー入力がバリデーションされている
- [ ] SQLインジェクション対策（パラメータ化クエリ）
- [ ] XSS対策（出力エスケープ）
- [ ] コマンドインジェクション対策
- [ ] リクエストサイズ制限

## HIGH — マージ前に確認

### H1. エラーハンドリング
- [ ] 例外がキャッチされず漏洩していない
- [ ] スタックトレースがクライアントに返されていない
- [ ] 適切なHTTPステータスコードが使用されている
- [ ] ビジネス例外と技術的例外が区別されている

### H2. API セキュリティ
- [ ] CORS設定が適切（ワイルドカード禁止）
- [ ] CSRFトークンが実装されている
- [ ] セキュリティヘッダーが設定されている（X-Content-Type-Options等）
- [ ] レート制限が実装されている

### H3. 通信セキュリティ
- [ ] TLS 1.2以上が使用されている
- [ ] データベース接続にTLSが使用されている
- [ ] 証明書の検証が有効になっている

## MEDIUM — 定期レビューで確認

### M1. 依存関係セキュリティ
- [ ] 依存ライブラリに既知の脆弱性がない
- [ ] セキュリティアップデートが適用されている
- [ ] 不要な依存関係が削除されている

### M2. パフォーマンス
- [ ] N+1クエリが発生していない
- [ ] 適切なインデックスが作成されている
- [ ] コネクションプールが設定されている

### M3. データ最小化
- [ ] 不要なデータが保持されていない
- [ ] データ保持期限が定義されている
- [ ] APIバージョニングが実装されている

## セキュリティインシデント対応プロトコル

開発中にセキュリティ脆弱性を発見した場合の対応手順:

### 即時対応（発見時）

1. **作業の停止** — 現在のタスクを中断する
2. **影響範囲の特定** — 脆弱性の影響を受けるコード・データの範囲を特定
3. **重大度の判定** — CRITICAL / HIGH / MEDIUM / LOW を判定

### 修正フロー

| 重大度 | 対応期限 | エスカレーション |
|--------|----------|----------------|
| CRITICAL | 即座に修正、他のタスクに優先 | ユーザーに即座に報告 |
| HIGH | 現在のPR完了前に修正 | ユーザーに報告し修正方針を確認 |
| MEDIUM | 次のPRで修正 | コンテキストファイルに記録 |
| LOW | バックログに追加 | コンテキストファイルに記録 |

### 修正後の確認

1. **クレデンシャルのローテーション** — シークレットが露出した場合は即座にローテーション
2. **類似パターンの検索** — コードベース全体で同様の脆弱性がないか `grep` で検索
3. **リグレッションテスト** — 修正が他の機能を壊していないか検証
4. **ADR への記録** — セキュリティ判断は ADR として記録し、フィットネス関数を定義
